# 결제 기능 출시 점검표

## 자동 검증

- 백엔드 전체 단위·계약 테스트가 통과한다.
- 프런트엔드 TypeScript 검사와 Production 빌드가 통과한다.
- `vercel.json`의 이용권 만료 작업이 `/api/billing/cron/subscriptions/expire`를 매일 호출한다.
- `/api/health`가 인증 없이 200을 반환한다.
- 로그인하지 않은 `/api/billing/plans` 요청은 401을 반환한다.
- 인증 헤더가 없는 Cron 요청은 401을 반환하며 작업을 실행하지 않는다.

## Vercel Production 설정

- `NEXT_PUBLIC_API_URL=/api`
- `DATABASE_URL`: 운영 Neon PostgreSQL 연결 문자열
- `JWT_SECRET_KEY`: 운영 전용 비밀값
- `TOSS_SECRET_KEY`: 현재 운영 단계에 맞는 토스 시크릿 키
- `NEXT_PUBLIC_TOSS_CLIENT_KEY`: 시크릿 키와 같은 테스트·라이브 환경의 결제창 클라이언트 키
- `CRON_SECRET`: 16자 이상의 무작위 비밀값, Production 적용
- 환경변수 변경 후 Production 재배포 완료
- Vercel `Settings → Cron Jobs`에 만료 작업 표시

## 역할별 회귀 테스트

### 학생·교수자

1. 역할에 맞는 요금제만 조회되는지 확인한다.
2. 테스트 결제를 완료하고 결제 완료 화면과 이용권 종료일을 확인한다.
3. 결제내역에 주문이 표시되고 유료 AI 기능의 일일 사용량이 증가하는지 확인한다.
4. 환불을 신청하고 중복 신청이 차단되는지 확인한다.

### 관리자

1. 결제·환불 신청·이용권·AI 사용량·웹훅 이력 화면을 확인한다.
2. 환불 승인 또는 반려 후 사용자 화면과 결제 상태가 일치하는지 확인한다.
3. 실패 웹훅의 `다시 검증`은 실패 이벤트에서만 노출되는지 확인한다.
4. 만료 상태 정리를 반복 실행해도 이미 만료된 이용권이 다시 변경되지 않는지 확인한다.

## 운영 전환 보류 항목

- 사업자 등록과 토스 이용 신청 전에는 테스트 키를 유지한다.
- 라이브 키 전환 전 실제 결제·취소·환불 시나리오를 소액으로 다시 검증한다.
- 자동결제, 부분 환불, 정산 자동화는 현재 30일 일회성 이용권 범위에 포함하지 않는다.
